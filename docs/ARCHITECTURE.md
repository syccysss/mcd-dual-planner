# 架构说明

## 1. 分层结构

```text
┌─────────────────────────────────────────────────────────────┐
│  bin/mcd-dual.mjs          命令行入口：参数解析 / doctor / plan │
└───────────────┬─────────────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────────────┐
│  src/pipeline.mjs          编排：取数 → 匹配 → 求解 → 验价     │
│    ├── buildPlanDemo()     离线分支（读 demo-data.mjs）       │
│    ├── buildPlanLive()     实时分支（读 MCP）                 │
│    └── cache.mjs           菜单+算价本地缓存（TTL 30 分钟）    │
└───┬───────────┬───────────┬───────────┬─────────────────────┘
    │           │           │           │
    ▼           ▼           ▼           ▼
 mcp-client  tools.mjs   normalize   solver.mjs      report.mjs
 传输/限流    白名单+     字段/单位    约束枚举/        SVG 渲染
 脱敏/错误    schema 映射  名称匹配     券后实付+        CJK 折行
                                      帕累托前沿
                │
                ▼
        ┌───────────────┐
        │ mcd.mcd.cn    │  麦当劳中国 MCP Server（只读调用）
        └───────────────┘
```

**依赖方向是单向的**：渲染层不知道数据来自哪里，求解器不知道 MCP 的存在。
`pipeline.mjs` 是唯一同时接触「外部数据」与「内部算法」的模块，因此演示与实时两条分支
在此汇合成同一个结果对象，下游完全复用。

## 2. 关键设计决策

### 2.1 为什么零依赖

参赛项目要经得起评审 `git clone` 后立刻运行。引入 MCP SDK 会带来 `npm install`、
锁文件与网络依赖，而本项目只需要 `initialize` / `tools/list` / `tools/call` 三个方法，
用内置 `fetch` 手写不到 300 行，还顺带把限流、脱敏、SSE 解析做成了可控的实现。

### 2.2 为什么参数名要做自适应映射

官方工具的参数名会随版本演进。硬编码 `beCode` 一旦碰到 `storeCode`，请求会「成功」但取到空数据——
这是最难排查的一类 bug。`tools.mjs` 的 `mapParams()` 在运行时读取 `inputSchema`，
按归一化名称匹配真实参数名，匹配不上的参数**上报而不是发出**。

### 2.3 为什么演示与实时彻底隔离

「看起来像真数据的假数据」是这类工具最危险的失败方式。因此：

- 演示数据集中在 `demo-data.mjs`，每个条目带 `demo: true`；
- 战报页眉用不同颜色的徽标区分「演示数据」与「实时数据（官方 MCP）」；
- 实时模式任一步失败**直接抛错退出**，绝不回落到演示数据；
- 数据口径说明里逐条写明本次数据的来源与已知局限。

### 2.4 为什么推断必须留痕

单位换算（kJ→kcal、g→mg）、品类推断、套餐营养累加都会产生 `inferred` 标记，
一路传到战报的「数据口径与说明」。用户看到 `478 kcal` 时应当知道这是从 `2000 kJ` 换算来的，
而不是官方直接给出的数字。

### 2.5 为什么网页 demo 内联同一份求解器

`tools/build-web-demo.mjs` 在生成时把 `src/normalize.mjs` / `src/solver.mjs` 的**源文件**
按 `import/export` 剥离后包成 IIFE，直接内联进单文件 HTML，而不是另写一份"网页版算法"。
这样做的唯一目的是**避免口径漂移**：一旦网页与命令行各维护一份逻辑，两者迟早会对不上，
而这种差异在 demo 里极难被发现。网页端与 CLI 使用同一份代码、同一份数据快照，
因此结论数字逐一对得上（118 项菜单 → 70 候选 → 1,999 预算内 → 28 达标）。

## 3. 错误处理

| 场景 | 行为 |
|---|---|
| 缺少 Token | 构造客户端时即抛错，提示申请入口与设置方式 |
| `401/403` | 归类为 `auth`，提示重新申请 Token，**不重试** |
| `429` | 归类为 `rate_limit`，提示降低频率，**不循环重试** |
| `404` | 视为会话过期，清空 `Mcp-Session-Id` 后重新握手一次（仅一次） |
| 超时 | `AbortController` 控制，归类为 `timeout`，提示调大 `--timeout-ms` |
| SSE 解析失败 | 归类为 `protocol`，保留脱敏后的响应片段便于排查 |
| 单个套餐拆解失败 | 记录后继续，不影响整体求解 |
| 券查询失败 | 计入「无券」口径并记录失败原因 |
| 验价失败 | 逐条写入战报的失败清单，不用本地价冒充官方价 |

## 4. 安全边界

- `src/tools.mjs` 维护**只读白名单**与**写操作黑名单**，黑名单优先且直接抛错；
- `tests/security.test.mjs` 断言所有写操作都被拒绝、白名单里不含写操作；
- Token 只存在于 `McpClient` 的私有字段，`describe()` 与 `toJSON()` 均不返回其内容；
- 所有进入错误信息的上游文本都经过 `redact()`，含 `Bearer …` 兜底正则；
- 有一条测试扫描整个仓库，确保没有文件包含形似真实 Token 的字符串；
- 网络请求头 `mcp-protocol-version` 固定为 `2025-06-18`，不随用户输入变化。

## 5. 扩展点

| 想做的事 | 改哪里 |
|---|---|
| 换一套营养目标权重（增肌 / 控糖 / 控钠） | `src/solver.mjs` 的 `DEFAULT_WEIGHTS` / `DEFAULT_TARGETS` |
| 改品类规则（例如允许 2 个主食） | `src/solver.mjs` 的 `DEFAULT_RULES` 或通过 `solve({ rules })` 传入 |
| 支持外送场景 | `pipeline.mjs` 里把 `beType` 换成外送对应值，并接入 `delivery-query-stores` |
| 更接近穷举 | `--per-category` 调大，注意枚举规模与耗时 |
| 换输出形式（HTML / PNG / 终端） | 新增渲染模块，复用 `pipeline` 产出的同一结果对象 |
| 增加新的只读工具 | 在 `READ_ONLY_TOOLS` 中登记，并在 `pipeline` 中编排 |
